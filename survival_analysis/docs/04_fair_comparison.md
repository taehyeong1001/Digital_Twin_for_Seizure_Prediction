| 축 | 기존 (final_code) | 우리 (survival_dist) |

## 2. 지금까지의 비교가 공정하지 않은 지점

### C1. 예측에 쓰는 rollout 수가 다르다 (가장 큰 문제)
- **정정 (2026-10-13, 코드 확인):** 처음에는 "멤버 0의 예측은 시행마다 0/1"이라고 적었는데 틀렸다.
  - 우리 지표(1·2단계, `dist_report.py`)는 시행 i의 예측을 **그 시행이 속한 x0 수준의 이탈 빈도**로 둔다. 원본 `grouped_survival`과 같은 방식이다.
  - 그래서 멤버 0의 예측도 0/1이 아니다. 수준마다 rollout R개(single 10 또는 20, 다중 노드 8)의 빈도다.
- 앙상블은 같은 빈도를 rollout 20·R개로 계산한다.
  - 따라서 차이는 예측의 "형태"가 아니라, **확률 추정에 들어가는 rollout 수와 그에 따른 표본 잡음**이다.
  - 예: R = 8이면 멤버 0의 확률은 1/8 단위로만 나온다.
- 따라서 "앙상블 Brier < 멤버 0 Brier"의 이유는 둘 중 하나일 수 있다.
  - (a) reservoir가 여러 개라서
  - (b) 단지 rollout이 20배 많아서
- **(b)는 reservoir 하나로도 할 수 있다.** 같은 reservoir에 innovation 노이즈만 바꿔 시행당 K = 20번 rollout하면 된다 (arm B).

### C2. 멤버 0은 홈 어드밴티지가 있다
- 다중 노드 BO는 모든 시행에서 reservoir seed를 `SEED + 900`(= 멤버 0)으로 고정했다. 하이퍼파라미터가 **그 reservoir에 맞춰** 골라졌다.
- single node BO는 후보마다 seed가 달라서, 사실상 seed까지 함께 골랐다.
- 그래서 멤버 1–19는 "남의 하이퍼파라미터"를 쓰는 셈이다. 앙상블 vs 멤버 0 비교에서는 멤버 0이 구조적으로 유리하다.
  - 예: 3-node rate 모델 120 s에서 멤버 0(0.009)이 앙상블(0.016)보다 나았다. 이 결과는 이 효과로 설명될 수 있다.
- 기존 프레임워크를 "방법"으로 평가하려면, seed를 임의로 하나 골랐을 때의 기대 성능(**멤버 점수의 분포**)이 맞는 비교 대상이다. 멤버 0은 운 좋게 튜닝된 한 점이다.

### C3. single node는 cohort가 다르다
- 기존 MAE 0.077은 coarse 260 시행에서 나왔다.
- 우리 2단계 수치는 coarse + fine 880 시행을 합친 값이다. fine은 전이 구간에 몰려 있어서 어려운 시행이 많다.
- 멤버 0의 Brier가 0.065(coarse)에서 0.30(fine)으로 변한 것은 **모델이 아니라 cohort가 바뀐 결과**다.
- 따라서 single node에서는 같은 cohort 안에서만 비교한다 (coarse끼리, fine끼리). 합친 수치는 보조로만 쓴다.

### C4. 지표가 엇갈려 있다
- 기존 모델은 새 지표로 채점했다 (1단계). 그런데 **앙상블은 기존 MAE로 채점한 적이 없다.**
- MAE와 Brier는 가중치가 다르다 (x0 수준마다 같음 vs 시행마다 같음). 그래서 한 표 안에서 섞어 읽으면 안 된다.
- 필요한 것은 모든 예측자 × 모든 지표의 **교차표**다.

### C5. horizon
- 기존 결과는 H 하나에서만 나온다. 우리는 여러 h를 보고했다.
- 기존과 비교하는 주 수치는 **H**로 하고, 다른 h는 보조로 둔다. h를 골라 보고하면 유리한 h만 고르는 문제가 생긴다.

### C6. 다중 노드의 "기존 모델"이 저장소 그림의 모델이 아니다
- robust 최종 모델은 재실행에서 재현되지 않았다. 우리가 쓴 것은 같은 파이프라인이 만든 rate / peak 모델이다.
- 그래서 `final_figures/multi_node`의 숫자와 우리 앙상블을 직접 비교하면 안 된다. **재실행의 멤버 0**과 비교한다.
- 시점 지표는 BLAS 스레드 수에 따라 1–2 s 달라진다. 비교하는 모든 예측자를 같은 실행 환경에서 돌린다.

### C7. 시스템 간 비교표는 교란되어 있다
[03](03_progress_log.md)의 "세 시스템 비교" 표에서 single node와 다중 노드는 노드 수 말고도 많은 것이 다르다.

| | single node | 다중 노드 |
|---|---|---|
| 이벤트 | 국소 최소 ≤ −2.0, blanking 없음 | ≤ −0.5, 5 s blanking |
| H | 140 s | 120 s |
| 학습 데이터 | 정상 궤적만 | 정상 + 이탈 궤적 (`event_signals`) |
| BO | GP-BO 24회 | 100 + 100 + 100회 + 확인 단계 |
| reservoir 크기 | 280 | 1,500 |
| BO 선택 조건 | clip 조건 없음 | clip 비율 0 |
| BO의 reservoir seed | 후보마다 다름 | 고정 |

- 그래서 "single node는 나쁘고 다중 노드는 좋다"를 **노드 수의 효과로 해석할 수 없다.**
- 이 표는 "각 시스템의 원래 파이프라인이 내놓은 모델의 상태"로만 읽어야 한다.

### C8. GT 비율 자체가 잡음을 가진다
- GT 비율은 x0마다 8–10개 시행으로 낸 값이다. 완벽한 모델도 기존 MAE가 0이 되지 않을 수 있다.
- 우리는 독립 GT seed로 만든 **oracle**이 있다. oracle의 MAE를 같이 적으면 "이 cohort에서 도달할 수 있는 하한"이 된다.
  - 다만 GT의 H 시점 생존이 계단이라 이번 cohort들에서는 oracle MAE도 거의 0일 것이다. 짧은 h에서는 0이 아니다.

## 3. 공정한 비교를 위한 설계

### 3.1 먼저 질문을 나눈다
질문마다 맞는 비교 대상이 다르다. 섞으면 C1·C2 같은 문제가 생긴다.

| 질문 | 비교 | 비고 |
|---|---|---|
| **Q1. 산출물:** 저장소의 그 모델이 GT와 맞나? | 멤버 0 vs GT | 기존 프레임워크가 답하던 질문. 홈 어드밴티지는 문제가 아니다 |
| **Q2. 방법:** 이 하이퍼파라미터 + 임의의 seed로 만든 RC가 맞나? | 멤버별 점수의 분포 (중앙값, 5–95%) vs GT | 재현성 질문. seed에 대한 강건성 |
| **Q3. 앙상블의 가치:** reservoir를 여러 개 쓰면 하나보다 나은가? | 아래 3.2의 짝 비교 | C1을 통제해야 답할 수 있다 |

### 3.2 예측자(arm) — 모두 같은 GT 시행, 같은 이벤트 정의, 같은 H, 같은 실행 환경

| arm | 내용 | 시행당 rollout | 상태 |
|---|---|---|---|
| A | 멤버 0, rollout 1회 (기존 그대로) | 1 | 있음 |
| **B** | **멤버 0, innovation seed만 바꿔 K = 20회** | 20 | **새로 필요** |
| C | 멤버 j 각각, rollout 1회 → 점수의 분포 | 1 | 있음 (`per_member.csv`) |
| **D** | **멤버 j 각각, K = 20회** → 점수의 분포 | 20 | **새로 필요** (비용이 크면 멤버 일부만) |
| E | 앙상블: 20 멤버 × 1회 (현재) | 20 | 있음 |
| **F** | 멤버 0을 뺀 19 멤버 앙상블 | 19 | 재분석만 하면 됨 |
| 기준선 | oracle, climatology, x0를 무시한 KM | — | 있음 |

**읽는 법:**
- **E vs B:** 계산량(20회)과 예측 형태(비율)를 맞춘 상태에서 "reservoir가 다양한 것"의 가치. Q3의 핵심 비교다.
- **E vs D의 중앙값:** 임의 멤버 하나로 K번 돌린 것보다 나은가. 홈 어드밴티지가 없는 Q3이다.
- **F vs A, F vs B:** 튜닝된 seed 없이도 앙상블이 튜닝된 단일 모델을 이기는가. C2를 통제한다.
- **B vs A:** 같은 reservoir에서 확률을 낸 것만으로 얼마나 좋아지는가. 기존 프레임워크도 거의 공짜로 얻을 수 있는 개선이다.
- 덤으로, B와 D가 있으면 불확실성 분해가 깔끔해진다. 지금은 멤버마다 reservoir seed와 innovation seed가 같이 바뀐다. B/D가 있으면 "같은 reservoir 안의 노이즈 변동"을 따로 잴 수 있다.

### 3.3 지표 — 모든 arm에 모두 적용 (교차표)
1. **기존 MAE**
   - 예측된 생존율 = 1 − (시행별 p를 x0 안에서 평균). 이것과 GT 비율의 MAE를 x0 수준마다 같은 가중치로 계산한다.
   - oracle의 MAE를 하한으로 함께 적는다 (C8).
2. **시행 단위 Brier (H)**와 Murphy 분해. 주 지표다.
3. **IBS, D-calibration** (시점).
4. **x50(H)**.

single node는 위 표를 **coarse와 fine에 따로** 만든다 (C3). 주 수치는 h = H로 하고, 다른 h는 부록으로 둔다 (C5).

### 3.4 차이의 불확실성
- 모든 arm이 같은 GT 시행을 쓴다. 그래서 **짝지은 차이**(시행별 Brier 차이 등)로 비교한다.
- 구간은 **x0 수준 단위 cluster bootstrap**으로 낸다. 같은 x0 안의 시행들은 같은 조건을 공유하므로, 시행 단위로 다시 뽑으면 구간이 지나치게 좁아질 수 있다.
- 멤버 분포(C, D)는 5–95% 범위로 보고한다. 멤버 20개라 꼬리 추정은 거칠다는 점을 함께 적는다.

### 3.5 시스템 간 비교 (C7)
- 최소한의 조치: 시스템 비교표에 "원래 파이프라인끼리의 비교이며 노드 수 효과가 아님"을 명시한다.
- 노드 수 효과를 말하고 싶다면 교란 요인을 하나씩 맞추는 분리 실험이 필요하다. 비용이 싼 순서로:
  1. **이벤트 정의 맞추기:** single node 궤적에 다중 노드 정의(≤ −0.5, 5 s blanking)를 적용해 다시 검출한다.
     - 멤버 체크포인트(`member_XXXX.npz`)에는 **이벤트 시각만 있고 궤적은 없다** (2026-10-13 확인). 그래서 rollout을 다시 해야 한다. 학습은 다시 할 필요가 없다 (seed로 재현된다).
     - 단, single node 신호의 정상 진폭에서 −0.5가 의미 있는 경계인지 먼저 확인해야 한다.
  2. H를 맞춘다 (120 s로 자르기). 저장된 이벤트 시각만으로 재분석할 수 있다.
  3. 학습 데이터, BO 예산, reservoir 크기, clip 조건은 재학습이 필요하다. 모델링 범위라서 팀 결정이 필요하다.

| single node: 멤버 0 Brier 0.065 → 0.30 | C3. 모델 변화가 아니라 cohort 차이 | 문구를 "cohort가 어려워져서"로 고친다 (03에는 이미 그 뜻으로 적혀 있음) |

oracle, climatology, KM 기준선과의 비교는 공정하다. 같은 시행과 같은 정의를 쓰기 때문이다.

   - 앙상블과 단일 결정론적 예측을 같은 계산량으로 비교하는 관행 (기상 예보 검증)
   - 짝지은 예측 비교의 검정 (Diebold–Mariano 계열 등)
   - deep ensemble에서 seed만 바꾼 앙상블의 해석
   - 확인 수준을 표시해서 plan §2에 추가한다.

### 6.3 해석

1. **rollout 수를 맞추면, 앙상블이 단일 reservoir보다 낫다는 증거가 없다 (E vs B).**
   - Brier와 IBS 모두 네 cohort에서 E − B의 CI가 0을 포함한다.
   - 기존 MAE로는 single node에서 앙상블이 **유의하게 더 나쁘다**.
   - 그래서 03에 적은 "앙상블이 멤버 0보다 낫다"는 주장은 이렇게 고친다.
     - 2-node (0.003 vs 0.008): 차이의 절반가량은 rollout을 늘린 것(B = 0.006)으로도 얻는다. 나머지는 통계적으로 구분되지 않는다.
     - single node (0.204 vs 0.229): cohort를 합쳐서 생긴 수치다. coarse에서는 오히려 E가 나쁘다.

2. **같은 reservoir 안의 노이즈 반복(B − A)은 효과가 작다.**
   - single node에서는 거의 0이다. arm B의 이탈은 100% clip 포화다. 즉 이 RC는 x0가 정해지면 노이즈와 무관하게 거의 결정론적으로 발산하거나 버틴다.
   - 다중 노드에서는 작은 개선이 있다. 2-node IBS만 CI가 0을 벗어난다.
   - 결론: final_code의 단일 RC 곡선에서 "rollout 표본이 적어서 생기는 잡음"은 결과를 바꿀 만큼 크지 않다.

3. **멤버 0의 홈 어드밴티지는 3-node에서 뚜렷하다.**
   - 3-node 멤버 0은 H(120 s)에서 20개 중 **1등**인데 h = 60 s에서는 **20등(꼴찌)**이다.
   - BO가 H 시점의 생존율에 맞춰 하이퍼파라미터를 골랐고(seed 고정), 그 seed에서 H 지표만 좋아진 것과 맞는 결과다.
   - 2-node에서는 멤버 0이 17등이라 이 효과가 보이지 않는다.
   - 따라서 기존 프레임워크의 3-node 곡선(MAE 0.023)은 "이 방법의 전형적인 성능"(멤버 중앙값 0.036)보다 낙관적이다.
   - 멤버 0을 빼도(F) 앙상블은 거의 변하지 않는다 (E − F는 모든 곳에서 |Δ| < 0.01). 앙상블은 멤버 0에 기대지 않는다.

4. **기존 MAE와 Brier가 반대 결론을 낼 수 있다 (single fine).**
   - fine에서 GT는 0/1 계단이다.
   - 앙상블 E는 전 구간에서 0.23–0.52의 거의 평평한 확률을 낸다.
   - 멤버 0은 18개 수준을 정확히 맞추고, 전이 근처 약 10개 수준을 완전히 틀린다 (0 vs 1).
   - 절대오차(MAE)는 "넓게 퍼진 중간값"을 더 벌주고, 제곱오차(Brier)는 "확신에 찬 오답"을 더 벌준다. 그래서 MAE는 A를, Brier는 E를 고른다.
   - 둘 다 climatology보다 나쁘다 (BSS < 0). 즉 fine에서는 어느 RC arm도 쓸 만하지 않다.
   - 절대오차는 확률 예측에 대해 proper scoring rule이 아니어서, 확률을 0/1 쪽으로 밀어붙이는 예측을 선호할 수 있다. 기존 MAE를 주 지표로 쓰면 이 편향이 들어간다.
     - 문헌 확인 (2026-10-13, 2차 출처 수준; [05](05_next_experiments.md) §4): 절대오차는 **중앙값**에 대한 점수이고, 예측이 예측분포의 중앙값일 때만 적절하다 (Gneiting 2011). 0/1 규칙은 proper지만 strictly proper가 아니다 (Gneiting & Raftery 2007, Example 4).
     - "0/1 쪽으로 끌린다"는 이 성질에서 나온 추론이고, 원문으로 직접 확인하지는 않았다.

5. **시스템 간 패턴은 그대로다.** 다중 노드는 모든 arm이 좋고 서로 가깝다. single node는 멤버 분포가 넓고 모든 arm이 시점을 못 맞춘다 (D-cal p < 1e-16). 다만 C7(교란)은 여전히 남아 있다.

### 6.4 그래서 "공정한 비교"의 결론
- **Q1 (산출물):** 기존 단일 RC는 자기 평가 기준(H, MAE)에서 여전히 가장 좋거나 비슷하다. 다만 3-node에서는 그 기준에 맞춰 튜닝된 결과라서, h를 바꾸면 순위가 뒤집힌다.
- **Q2 (방법):** 다중 노드는 seed에 강건하다 (멤버 중앙값이 A에 가깝다). single node는 그렇지 않다 (멤버 중앙값 Brier 0.23–0.37).
- **Q3 (앙상블의 가치):** 이번 데이터로는 **입증되지 않는다.** 앙상블의 실제 기여는 성능 향상보다 **불확실성을 보여 주는 것**이다: 멤버 간 분포, seed 민감도, 단일 모델의 낙관 편향.
- 보고할 때 권장하는 형식:
  - 주 지표는 Brier와 IBS(proper)
  - 기존 MAE는 연속성을 위해 함께 적되, 주 지표가 아님을 밝힌다
  - 단일 모델 결과 옆에 항상 멤버 분포(C)와 rollout 수를 맞춘 대조군(B)을 같이 적는다
